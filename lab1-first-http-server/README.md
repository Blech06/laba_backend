## Цель работы
Освоить установку инструментов для бэкенд-разработки, создать и запустить минимальный веб-сервер, обрабатывающий GET-запросы, понять концепцию эндпоинтов, научиться настраивать автоматический перезапуск сервера.

---

## Теоретическое обоснование

**Бэкенд** — серверная часть веб-приложения, отвечающая за обработку HTTP-запросов от клиентов, выполнение бизнес-логики и формирование ответов. Взаимодействие строится по клиент-серверной архитектуре: клиент отправляет запрос, сервер обрабатывает его и возвращает ответ.

**Эндпоинт (endpoint)** — конкретный URL + HTTP-метод, по которому клиент обращается к ресурсу (например, `GET /api/books`). **Маршрут (route)** — механизм сопоставления пути запроса с функцией-обработчиком на сервере.

**JSON** (JavaScript Object Notation) — лёгкий текстовый формат обмена данными, ставший стандартом для REST API. Он легко читается человеком и парсится машинами.

Для автоматического перезапуска сервера при изменении кода используется **nodemon** (для Node.js). Это ускоряет разработку, избавляя от ручного перезапуска.

## Выполнение практического примера

### 1. Создание проекта и установка зависимостей

```bash
mkdir lab1-first-http-server
cd lab1-first-http-server
npm init -y
npm install express
npm install --save-dev nodemon
```

### 2. Настройка package.json

Добавлен скрипт:
```json
"scripts": {
  "start": "node app.js",
  "dev": "nodemon app.js"
}
```

### 3. Код сервера (базовый пример из методички)

```javascript
const express = require('express');
const app = express();
const port = 3000;

app.get('/', (req, res) => {
    res.send('Добро пожаловать на базовый сервер!');
});

app.get('/api/status', (req, res) => {
    res.json({ status: 'ok', uptime: process.uptime() });
});

app.listen(port, () => {
    console.log(`Сервер запущен на http://localhost:${port}`);
});
```

### 4. Запуск

```bash
npm run dev
```

Сервер стартует на `http://localhost:3000`. При изменении файла `app.js` nodemon автоматически перезапускает процесс.

## Выполнение индивидуального задания (Вариант 4)

Реализован **повышенный уровень**, который полностью покрывает требования базового и среднего уровней.

### Требования варианта 4 (повышенный)

| Требование | Реализация |
|------------|------------|
| Текстовый эндпоинт на `/` | `Welcome!` |
| JSON-эндпоинт 1 (коллекция) | `/api/books` — статический список книг |
| JSON-эндпоинт 2 (справочник) | `/api/authors` — статический список авторов |
| Эндпоинт с параметром | `/api/books/:id` |
| Обработка 404 | `{"error": "Not Found"}` |
| Консольное логирование | Middleware: метод + URL + время |
| Авто-перезапуск | `nodemon` через `npm run dev` |

### Полный код сервера (`app.js`)

```javascript
const express = require('express');
const app = express();
const port = 3000;

// Middleware: консольное логирование всех запросов
app.use((req, res, next) => {
    const timestamp = new Date().toISOString();
    console.log(`[${timestamp}] ${req.method} ${req.url}`);
    next();
});

// 1. Текстовый эндпоинт (вариант 4)
app.get('/', (req, res) => {
    res.send('Welcome!');
});

// 2. JSON-эндпоинт 1 — коллекция книг
app.get('/api/books', (req, res) => {
    res.json([
        { id: 1, title: 'Война и мир', author: 'Лев Толстой', year: 1869 },
        { id: 2, title: 'Преступление и наказание', author: 'Фёдор Достоевский', year: 1866 },
        { id: 3, title: 'Мастер и Маргарита', author: 'Михаил Булгаков', year: 1967 },
        { id: 4, title: 'Анна Каренина', author: 'Лев Толстой', year: 1877 },
        { id: 5, title: 'Идиот', author: 'Фёдор Достоевский', year: 1869 }
    ]);
});

// 3. JSON-эндпоинт 2 — справочник авторов
app.get('/api/authors', (req, res) => {
    res.json([
        { id: 1, name: 'Лев Толстой', country: 'Россия', birthYear: 1828 },
        { id: 2, name: 'Фёдор Достоевский', country: 'Россия', birthYear: 1821 },
        { id: 3, name: 'Михаил Булгаков', country: 'Россия', birthYear: 1891 },
        { id: 4, name: 'Антон Чехов', country: 'Россия', birthYear: 1860 },
        { id: 5, name: 'Александр Пушкин', country: 'Россия', birthYear: 1799 }
    ]);
});

// 4. JSON-эндпоинт с параметром /api/books/:id
app.get('/api/books/:id', (req, res) => {
    const bookId = req.params.id;
    res.json({
        requestedId: Number(bookId) || bookId,
        status: 'success',
        message: `Информация о книге с ID ${bookId}`,
        book: {
            id: Number(bookId) || bookId,
            title: 'Книга (заглушка)',
            available: true
        }
    });
});

// Дополнительно: эндпоинт базового уровня /api/health
app.get('/api/health', (req, res) => {
    res.json({
        status: 'healthy',
        uptime: '100s'
    });
});

// 5. Обработка 404
app.use((req, res) => {
    res.status(404).json({ error: 'Not Found' });
});

app.listen(port, () => {
    console.log(`Сервер запущен на http://localhost:${port}`);
});
```

### Проверка эндпоинтов

| URL | Ожидаемый результат |
|-----|---------------------|
| `http://localhost:3000/` | `Welcome!` (текст) |
| `http://localhost:3000/api/books` | JSON-массив книг |
| `http://localhost:3000/api/authors` | JSON-массив авторов |
| `http://localhost:3000/api/books/3` | JSON с `requestedId: 3` |
| `http://localhost:3000/api/books/42` | JSON с `requestedId: 42` |
| `http://localhost:3000/api/health` | `{"status":"healthy","uptime":"100s"}` |

## Контрольные вопросы

**1. Что такое клиент-серверная архитектура?**  
Модель взаимодействия, при которой клиент (браузер, мобильное приложение) отправляет запросы, а сервер (бэкенд) их обрабатывает и возвращает ответы. Клиент и сервер могут находиться на разных машинах и общаться по сети.

**2. Какой протокол используется для общения клиента и сервера в вебе?**  
HTTP (HyperText Transfer Protocol). В современных приложениях чаще используется HTTPS (с шифрованием).

**3. Что такое эндпоинт (endpoint)?**  
Конкретный адрес (URL) + HTTP-метод, по которому клиент обращается к серверу для выполнения определённой операции (например, `GET /api/books`).

**4. Какую структуру имеет HTTP-запрос и HTTP-ответ? Что такое код состояния (status code)?**  
HTTP-запрос: метод, путь, заголовки, тело (опционально).  
HTTP-ответ: статус-код, заголовки, тело.  
Код состояния — трёхзначное число, сообщающее результат обработки (200 — OK, 404 — Not Found, 500 — Internal Server Error и т.д.).

**5. Что такое JSON? Почему он популярен в веб-разработке?**  
Лёгкий текстовый формат обмена данными на основе JavaScript-объектов. Популярен благодаря простоте, читаемости, поддержке во всех языках и естественной интеграции с JavaScript.

**6. Как запустить сервер на Node.js или Flask?**  
Node.js: `node app.js` или `npm run dev` (с nodemon).  
Flask: `python app.py` (с `debug=True` для авто-перезапуска).

**7. Что такое автоматический перезапуск сервера и зачем он нужен? Какой пакет используется для Node.js?**  
Механизм, который отслеживает изменения файлов и перезапускает процесс. Нужен для ускорения разработки. Для Node.js — пакет **nodemon**.

**8. Какие коды состояния HTTP вы знаете? За что отвечает код 404?**  
200 OK, 201 Created, 400 Bad Request, 401 Unauthorized, 403 Forbidden, 404 Not Found, 500 Internal Server Error.  
404 означает, что запрошенный ресурс (маршрут) не найден на сервере.

**9. Что такое middleware в Express?**  
Функции, которые выполняются в цепочке обработки запроса до (или после) основного обработчика. Используются для логирования, аутентификации, парсинга тела запроса и т.д. В данном проекте middleware логирует каждый входящий запрос.

**10. Как получить параметр из URL-пути (например, ID) в Express?**  
Через объект `req.params`. Для маршрута `/api/books/:id` значение доступно как `req.params.id`.
